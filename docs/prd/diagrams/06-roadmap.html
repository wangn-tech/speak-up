实施路线图（MVP 到发布）
AI 英语口语陪练平台 · 设计示意 · 各阶段产出物与进入条件
阶段0
选型
技术选型定稿（进行中）ASR/TTS 供应商推荐、LLM（通义百炼 + DeepSeek，OpenAI 兼容协议）接入核验、向量库与 Embedding 选型 → 产出 .env 模板 → 回写 PRD 开放问题 Q1-Q5
↓
阶段1
骨架
仓库与基础设施骨架docker-compose.yml：MySQL、Redis、Kafka、向量库、AI 服务、后端、Prometheus、Grafana；.env.example 与配置加载；gRPC proto 契约（Conversation / Retrieval / Evaluation）
↓
阶段2
AI冒烟
AI 服务最小链路冒烟FastAPI + LangGraph 对话 Agent（LLM 走 OpenAI 兼容协议）；ASR/TTS 供应商 SDK 接入；目标：跑通「语音 → ASR → Agent → TTS」端到端并测量延迟预算
↓
阶段3
后端
后端服务（Go + Gin）认证 / 用户 / 场景 / 会话 API；gRPC 客户端对接 AI 服务；WebSocket 音频流代理；Kafka 事件（会话结束 → 复盘任务）；Prometheus 指标暴露 + Grafana 看板
↓
阶段4
前端
前端页面（React + TypeScript）门户 → 登录 → 工作台 → 场景广场 → 对话页（先文字后语音）→ 反馈页 → 复盘中心；WebSocket 音频流接入
↓
阶段5
管线
反馈与复盘异步管线Kafka Worker：转写对齐 → 并行评估（发音 / 语法 / 词汇 / 流利度 / 逻辑）→ 聚合评分 → 证据标注 → 报告生成 → 错题本与复习计划
↓
阶段6
发布
联调、验收与 MVP 发布端到端联调；延迟 / 并发压测；按 PRD 第 5 章验收标准逐项核对；指标基线上报（留存、完成率、反馈查看率）；灰度发布
你现在可以并行做的事：① 开通阿里云百炼与 DeepSeek 账号，准备两个 API Key（建议分开，便于成本核算与限流隔离）；② 确认 ASR/TTS 供应商后开通对应服务并充值小额度测试；③ 确定 Docker Desktop 环境可用（本机已具备 lark-cli，Docker 请自查）；④ 调研结论返回后，我将一次性给出推荐清单、.env 模板并回写 PRD。
